# Travel Planner

Личный мобильный планировщик путешествий. Интерфейс на английском; поездки, документы и расходы хранятся только в браузере на устройстве. Основное устройство — iPhone.

Адрес приложения: [открыть Travel Planner](https://lesyakudashova-creator.github.io/travelapp/).

Репозиторий: [lesyakudashova-creator/travelapp](https://github.com/lesyakudashova-creator/travelapp). Сайт и код публичные; сохранённые пользователем поездки и вложения в репозиторий не отправляются. Данные локального preview на компьютере не переносятся автоматически на этот адрес или на телефон.

## Возможности

- Поездки с обложками, городами и повторными периодами пребывания.
- Места с категориями, местными адресами, отметкой посещения и гибким планом дня.
- Отели и транспорт с документами PDF/JPEG/PNG/WebP (до 20 МБ каждый).
- Бюджет в AED с ручными курсами и автоматическим отражением стоимости бронирований.
- Установка на главный экран и базовая работа без интернета после подготовки приложения.

## Локальный запуск

Установите Node.js 22.12+ (LTS) с npm. В каталоге проекта:

```sh
npm ci
npm run dev
```

Откройте адрес, напечатанный Vite, с путём `/travelapp/`.

```sh
npm test
npm run build
npx playwright install chromium
npm run test:e2e
npm run preview
```

Офлайн-режим проверяется в production-сборке через `preview`, а не в режиме разработки. По умолчанию preview доступен по адресу `http://127.0.0.1:4173/travelapp/`.

В среде, в которой создавалось приложение, npm был загружен локально в `.tools/package`; вместо `npm` можно использовать `node .tools/package/bin/npm-cli.js`. Эта вспомогательная папка не публикуется. Для локально загруженных браузеров Playwright в PowerShell: `$env:PLAYWRIGHT_BROWSERS_PATH = "$PWD/.tools/browsers"`.

## Бесплатная публикация на GitHub Pages

1. Войдите в GitHub и создайте **публичный** репозиторий `travelapp`, без добавления стартового README.
2. В терминале каталога проекта выполните:

```sh
git init -b main
git add .github .gitignore README.md VERIFICATION.md e2e index.html package.json package-lock.json playwright.config.ts public src tests tsconfig.json vite.config.ts vitest.config.ts
git commit -m "Build Travel Planner PWA"
git remote add origin https://github.com/YOUR-USERNAME/travelapp.git
git push -u origin main
```

Замените `YOUR-USERNAME` своим логином. Авторизуйтесь через GitHub; не добавляйте пароли или токены в файлы проекта. `.gitignore` исключает зависимости, сборки и тестовые результаты. Перед отправкой убедитесь, что в каталог не добавлены личные билеты, фотографии и документы: публичный репозиторий доступен всем.

3. В репозитории откройте **Settings → Pages → Build and deployment → Source → GitHub Actions**.
4. В **Actions** дождитесь успешного workflow **Check and publish Travel Planner**. При необходимости запустите его через **Run workflow** после включения Pages.
5. Адрес приложения: `https://YOUR-USERNAME.github.io/travelapp/`.

Workflow сначала выполняет проверки, затем публикует только `dist`. При ошибке проверок публикация не выполняется. Последующие push в `main` обновляют приложение автоматически.

Если репозиторий называется иначе, сначала измените `base` в `vite.config.ts` и адреса в конфигурации браузерных тестов. Для выбранного имени `travelapp` ничего менять не нужно. Собственный домен и платный сервер не нужны.

Официальная инструкция: https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site

## Установка на iPhone

1. Откройте опубликованный HTTPS-адрес в Safari.
2. Выберите **Поделиться → На экран «Домой» → Добавить**.
3. Откройте приложение с появившейся иконки, пока есть интернет. Дождитесь подписи **Ready for offline use** на экране поездок.
4. Создавайте реальные поездки уже в этом установленном приложении; не полагайтесь на перенос данных между браузерами и режимами запуска.
5. Проверьте работу в авиарежиме: повторный запуск, план дня и документы.

При появлении **A new version is ready** сохраните работу и нажмите **Update**. В форме редактирования предложение обновления скрыто. Обновление оболочки не очищает IndexedDB.

## Данные и ограничения

Данные не уходят на GitHub или внешний сервер. GitHub раздаёт только программные файлы. Ссылки на карты и сайты открываются отдельно и могут требовать сеть. Приложение не запрашивает геолокацию и не содержит аналитики.

Данные привязаны к браузеру и адресу сайта. Очистка данных Safari, удаление данных сайта или изменение адреса могут сделать их недоступными. Локальное хранилище не является резервной копией. Синхронизации, экспорта и восстановления в первой версии нет; важные оригиналы билетов следует сохранять отдельно.

Вложения сохраняются как файлы в IndexedDB. Изображения открываются внутри приложения, PDF — в просмотрщике браузера. Просмотр PDF без сети и поведение файлов на iOS требуют отдельной проверки на реальном устройстве. Автоматические тесты Chromium не заменяют эту проверку.

Суммы вводятся с точкой или запятой. Валюта — трёхбуквенный код. Неуказанный курс делает итог неполным. Новое значение курса пересчитывает и уже оплаченные расходы. Стоимость места является оценкой и не учитывается в бюджете.

## Структура и развитие

- `src/model.ts` — типы, проверки, даты и денежные расчёты.
- `src/db.ts` — IndexedDB и транзакции сохранения/удаления.
- `src/App.tsx` — экраны, детали, бюджет и план дня.
- `src/forms.tsx`, `src/ui.tsx`, `src/styles.css` — формы и общая дизайн-система.
- `tests/`, `e2e/` — проверки бизнес-логики и браузерных сценариев.

Схема IndexedDB начинается с версии 1. Изменения схемы оформляйте новой версией Dexie и сохраняющей данные миграцией. Не используйте удаление базы как способ обновления. Контекст продукта и правила развития — в локальных `Product.md` и `AGENTS.md`; исходные материалы планирования не публикуются в этом репозитории.
